# pass_kuai — 진행 계획

> 최종 갱신: 2026-11-20 (출시 범위 변경: 로그인·설정을 1차에 추가, AI 통화는 2차)
> 처음 기획(카메라 분석 MVP)과 실제 구현이 달라진 부분이 있어 새로 썼습니다. 처음 기획에서 정한 결정은 맨 아래 "부록: 처음 기획 기록"에 남겨 두었습니다.

중국어 학습 앱. 중국어 문장을 분석해 번역·단어·병음·성조를 보여 주고, 단어장에 저장해 복습(SRS)하며, 따라 말하기로 발음을 확인합니다.

- 앱: Flutter (iOS / Android), `pass_kuai_app/` — 버전 `1.0.0+3`
- 서버: NestJS, `pass_kuai_server/` — LLM(Claude) 분석, STT, 기기 토큰 인증, 사용량 제한
- 코드 구조 문서: `docs/architecture/` ([table](architecture/table.md) · [repository](architecture/repository.md) · [model](architecture/model.md) · [provider](architecture/provider.md) · [router](architecture/router.md))

## 1. 지금 상태

### 1.1 기능 현황

| 기능 | 상태 | 비고 |
|---|---|---|
| 문장 분석 (텍스트 입력) | ✅ | 최대 1000자. 서버가 LLM 출력을 검증하고, 실패하면 422 + 한국어 안내 |
| 문장 상세 (성조 색, 단어 카드, TTS) | ✅ | |
| 단어장: 문장/단어 저장·목록·삭제 | ✅ | 같은 문장 = 원문이 같은 문장. 처음 저장한 것 유지 |
| 복습 (SRS 카드) | ✅ | 간격 [0,1,3,7,14,30]일, 탭 배지에 오늘 복습 수 |
| 따라 말하기 (발음 비교) | ✅ | 녹음 → 서버 STT → 음절 일치율 |
| 카메라/사진 분석 | ❌ 미구현 | 처음 기획의 핵심 기능이지만 출시 후로 미룸. `image_picker` 의존성 없음 |
| 받아쓰기 / 문장 카드 | ❌ 미구현 | 1차 출시 범위. 디자인 시안 있음 |
| 로그인 · 회원가입 · 아이디/비밀번호 찾기 | ❌ 미구현 | 1차 출시 범위. 처음 실행부터 로그인 필수, 이메일 인증 필수. 디자인 시안 있음 |
| 설정 · 계정 삭제 | ❌ 미구현 | 1차 출시 범위(App Store는 앱 안 계정 삭제 필수). 디자인 시안 있음 |
| AI 통화 | ❌ 미구현 | 2차 출시. 디자인 시안 있음 |

### 1.2 처음 기획에서 바뀐 것

| 처음 기획 | 실제 | 이유 / 메모 |
|---|---|---|
| 사진 → LLM Vision 분석 | 텍스트 입력 → LLM 분석 | 카메라는 출시 후로 미룸(4장 로드맵) |
| 서버리스 프록시 1개 | NestJS 서버 (인증·사용량 제한·메트릭·검증 포함) | |
| 온디바이스 STT (`speech_to_text`) | 녹음(`record`) → 서버 STT | |
| `SavedWord(hanzi, initial, final, tone, isFavorite…)` 단일 테이블 | `words`/`sentences`/`sentence_words` 원본 + `saved_*` 북마크 구조 | 실제 스키마는 [table.md](architecture/table.md) |
| `UNIQUE(hanzi)` | 단어 `UNIQUE(word, pinyin, translation)`, 문장 `UNIQUE(sentence)` | 같은 한자라도 병음·뜻이 다르면 다른 단어(行 xíng/háng) |

### 1.3 2026-11-19 정리에서 바뀐 것 (요약)

- **구조**: 이름·위치 정리(`lib/database/`, `lib/mapper/`, repository 메서드 이름 규칙, provider 파일 규칙), `Word` 이름 충돌 해결(`WordAnalysis`)
- **DB 스키마 v4 → v7**
  - v5: 같은 단어가 두 번 나오는 문장(我爱我家) 저장 실패 수정, 단어 순서 보장(`sentence_words.position`)
  - v6: 원문 유니크. 기존 중복 문장은 저장된 행을 우선 남기고 병합
  - v7: 옛 버전에서 깨진 채 저장된 `syllables`(음절 JSON)를 지움. 단어 행은 남기고 음절만 `[]`로 비움(성조 색만 빠짐)
- **저장**: 연타 방지, 문장 저장을 트랜잭션 하나로(동시 저장해도 1행), 실패하면 스낵바로 안내
- **길이 검사**: 서버가 1차로 검증하고, 앱 DB는 최후 방어선(서버 상한 ≤ 앱 상한)
- **복습 배지**: 자정이 지나거나 앱으로 돌아오면 기준일 갱신
- **테스트**: 앱 62개, 서버 단위 90개 + e2e 21개 (모두 통과)

## 2. 진행 원칙

- **1차 출시 범위(2026-11-20 변경)**: 디자인 캔버스 '최종' 페이지의 **1~5번 줄 + 7번 줄**입니다.
  - 1~2 로그인 · 회원가입 · 아이디/비밀번호 찾기
  - 3~4 문장 분석 · 발음 연습 · 단어장 · 단어 복습 (지금 있는 기능에 로그인을 붙임)
  - 5 복습 모드 · 문장 카드 · 받아쓰기
  - 7 설정 · 계정 삭제 (설정 화면의 "AI 통화" 묶음은 1차에서 뺌)
  - 이것을 완성하면 배포합니다. 그 밖의 기능은 4장 로드맵으로 미룹니다.
- **2차 출시**: 캔버스 **6번 줄(복습 연결 · 문법 카드)** + **8~13번 줄(AI 통화)**. 6번은 AI 통화에서 저장한 표현·문법을 복습하는 화면이라, 통화 기능 없이는 보여 줄 데이터가 없어 통화와 함께 냅니다.
- (이전 결정 2026-11-19: 출시 범위 = 지금 있는 기능 + 받아쓰기·문장 카드. 로그인 필수 결정으로 위와 같이 바뀜)
- **배포는 1차 범위를 다 만든 뒤 한 번** 합니다. LLM 사용 제한 문제(Step 3)도 그 전에 풀어야 합니다. 지금은 서버·앱 모두 배포하지 않습니다.
- 개발 중 확인은 **로컬에서 가짜 LLM(`pass_kuai_server/lab/mock-llm`)** 으로 합니다. 실제 Claude를 부르지 않아 사용량이 들지 않습니다.
- 실제 LLM으로 확인하는 건 꼭 필요한 경우만, 최소 건수로 합니다(예: 프롬프트나 서버 검증 규칙을 바꾼 직후 몇 문장).

## 3. 지금 할 일 (순서대로)

### Step 1. 이번 변경을 로컬에서 확인 (배포 없이)
- [ ] 서버: `pass_kuai_server`에서 `npm run build && npm test && npm run test:e2e`
- [ ] 로컬 서버 + 가짜 LLM 켜기: `npm run lab:up` (서버 `http://localhost:3000`, 가짜 Claude `http://localhost:8080`, 자세한 건 `lab/README.md`)
- [ ] 앱을 로컬 서버에 연결해 실행
  - iOS 시뮬레이터: 기본값 `http://localhost:3000`
  - Android 에뮬레이터: 기본값 `http://10.0.2.2:3000`
  - 실제 기기: `flutter run --dart-define=API_HOST=<맥의 IP>`
- [ ] **옛 버전이 깔린 기기에 새 빌드를 덮어 설치**해서 마이그레이션(v4~v6 → v7) 확인. 테스트는 메모리 DB로만 돌렸기 때문에 이 단계가 꼭 필요합니다.
  - [ ] 단어장의 문장·단어, 복습 기록이 그대로 있는지
  - [ ] 저장된 문장을 열었을 때 단어 순서가 원래대로인지
  - [ ] `我爱我家`처럼 같은 단어가 두 번 나오는 문장이 저장되는지
  - [ ] 같은 문장을 다시 분석해 저장하면 "이미 단어장에 있어요"가 뜨는지
  - [ ] 저장 버튼을 빠르게 여러 번 눌러도 한 번만 저장되는지
  - [ ] (가능하면) 앱을 켜 둔 채 자정을 넘기거나, 다음 날 앱으로 돌아왔을 때 복습 배지가 바뀌는지

### Step 2. 남은 기능 개발 (1차 범위, 캔버스 줄 순서대로)
- [ ] **로그인 · 회원가입 · 이메일 인증 · 아이디/비밀번호 찾기** (캔버스 1~2번 줄)
  - 서버: 계정(아이디·비밀번호 해시·인증된 이메일), 이메일 인증 코드 발송, 아이디 찾기·비밀번호 재설정, 로그인 토큰
  - 앱: 지금의 기기 토큰 인증(`auth_interceptor`, `token_storage`)을 계정 인증으로 교체. 처음 실행 → 시작 화면 → 로그인
  - 서버 사용량 제한을 기기 단위에서 계정 단위로 바꿀지 확인
- [ ] 분석·발음 연습·단어장·복습을 로그인 상태에 붙이기 (캔버스 3~4번 줄)
  - 앱은 **온라인 전용**(2026-11-21 결정): 단어장·복습 기록은 서버가 원본, 앱 drift DB는 제거, SRS 계산은 서버로. 오프라인 복습은 나중([database.md](../../pass_kuai_server/docs/database.md) 7장)
- [ ] **받아쓰기 + 문장 카드** 구현 (캔버스 5번 줄, 디자인 시안 있음)
- [ ] **설정 · 계정 삭제** (캔버스 7번 줄). 각 탭 헤더 오른쪽 위 프로필 아이콘으로 진입. 로그아웃, 계정 삭제(서버 데이터까지 삭제)
- [ ] 5장 백로그의 "바로 해도 좋은 것" 중 출시 전에 할 것 고르기 (특히 검색 데이터 정리, 당겨서 새로고침)
- 받아쓰기·문장 카드는 LLM을 쓰지 않으므로 가짜 LLM 없이도 개발할 수 있습니다. 저장된 문장이 필요하면 로컬 서버(`lab:up`)로 문장을 몇 개 분석·저장해 두고 씁니다.

- [x] **이 앱을 실제 사용자에게 배포한 적이 있나요?** (TestFlight, 내부 테스트 포함) → **없음** (2026-11-21). 옛 DB 파일 이전·기기 단어장 이전 모두 필요 없음. 서버 DB 설계 초안: [pass_kuai_server/docs/database.md](../../pass_kuai_server/docs/database.md)

- [ ] LLM 사용 제한을 어떻게 풀지(요금제·한도 상향 등). 배포 시점을 정하는 조건입니다.

- [ ] 계정 삭제 때 서버 데이터를 지우는 시점(바로 / 7일 안에)과 삭제 유예 기간. 개인정보 처리방침 문구와 맞춥니다.

## 4. 기능 로드맵

| 순서 | 기능 | 내용 | 메모 |
|---|---|---|---|
| 1차 | **로그인 · 회원가입 · 계정 찾기** | 아이디+비밀번호, 이메일 인증 필수(아이디 찾기·비밀번호 재설정에 사용). 소셜 로그인(카카오·Apple·Google) 포함 | 캔버스 1~2번 줄 |
| 1차 | **받아쓰기 + 문장 카드** | 복습 탭에서 모드 선택(단어 카드 / 문장 카드 / 받아쓰기). 받아쓰기는 한국어 뜻만 보고 중국어 입력 → 앱 안에서 글자 비교로 채점(LLM 안 씀, 성조 표시 없음). 틀린 문장은 '틀린 문장 다시 하기'에 모아 나중에 다시 풀기 | 저장 문장 활용. 문장 카드는 앞면(중국어만) → 단어 보기(힌트)/뜻 보기 → 확인 후 알았어요/몰랐어요. 캔버스 5번 줄 |
| 1차 | **설정 · 계정 삭제** | 내 계정, 로그아웃, 약관, 계정 삭제 | 캔버스 7번 줄. "AI 통화" 묶음은 2차 |
| 2차 | **AI 통화** | 샤오콰이와 실시간 중국어 음성 통화. 내 말은 실시간 받아쓰기, AI 대답 스트리밍, 말풍선마다 한국어 번역. 끝나면 요약·새 표현·문법·내 문장 고쳐 주기. 내 목소리 녹음은 항상 저장(기기+서버), 통화 기록 삭제 시 함께 삭제 | 캔버스 8~13번 줄. 실시간 스트리밍(STT·LLM·TTS) 구조가 새로 필요. 사용량: 계정당 하루 10분, 연결된 전체 시간 합산, KST 0시 초기화(정책 메모는 캔버스 13번 줄) |
| 2차 | **복습 연결 · 문법 카드** | 통화에서 저장한 단어는 단어 카드 SRS에 합침, 문법은 문법 카드, 고친 문장은 문장 카드·받아쓰기로 | 캔버스 6번 줄. 통화 데이터가 있어야 해서 통화와 함께 |
| 출시 후 1 | 단어장 성조 색 | 저장 단어 목록에도 성조 색 표시 | `word.syllables`가 이미 있어 작음 |
| 출시 후 2 | 단어장 검색·정렬 | 한자/병음/뜻 검색 | |
| 출시 후 3 | **카메라/사진 분석** | 사진 촬영·선택 → 서버(LLM Vision) → 같은 `AnalyzeResult` 응답 | 출시 후 기능 중 마지막. 서버 검증·앱 저장 경로는 그대로 재사용 가능 |
| 나중 | 성조 정밀 채점, 통계/스트릭 | | 단어장 서버 저장은 1차로 당겨짐(2026-11-21) |

## 5. 백로그 (코드 정리 / 남은 위험)

### 바로 해도 좋은 것 (작고 위험 낮음)
| 항목 | 내용 |
|---|---|
| 검색 데이터 정리 | 단어장에서 지운 문장·단어 원본이 DB에 남음. `cleanupSearchData`를 앱 시작 때(스플래시) 호출 |
| `AnalyzeRepository` 응답 타입 | `dio.post<Map<String, dynamic>>` + `?? {}` (`SttRepository`와 같게) |
| 당겨서 새로고침 | `ref.refresh(provider.future)`로 다시 불러올 때까지 기다리기 |
| dispose | `dbProvider`, `dioProvider`에 `ref.onDispose` |
| 라우터 | `debugLogDiagnostics`를 `kDebugMode`로, `errorBuilder` 추가 |
| 안 쓰는 메서드 삭제 | `findAll`, `findById`류, `SentenceWordRepository.deleteBySentenceId` |
| `ref` 안 쓰는 Consumer | `VocabScreen`, `_CardView`를 일반 위젯으로 |

### 알고 있는 위험
| 위험 | 영향 | 대응 |
|---|---|---|
| 서버 검증이 정상 LLM 출력을 막을 수 있음 | 분석 실패(422) | 배포 전 실제 LLM으로 소량 확인, 배포 후 로그 보고 규칙 조정(Step 4) |
| 빈 뜻/병음이면 저장 실패 | 저장 실패 스낵바 | 서버 검증이 빈 값을 422로 먼저 막음. 옛 서버 응답만 해당 |
| 원문 비교는 완전 일치 | 공백·문장부호만 다른 문장은 따로 저장됨 | 필요하면 정규화(공백 제거 등) 후 비교 |
| `extra`로 화면에 객체 전달 | 딥링크/재시작 시 "정보 없음" 화면 | 딥링크가 필요해질 때 id 기반 경로로 변경 |
| `passQuai` → `passKuai` DB 이름 변경 | 그 전에 설치한 사용자 데이터 미이전 | Step 3 답에 따라 결정 |
| LLM 사용 제한 | 배포하면 한도 초과 가능 | 출시 범위 완성 + 한도 문제 해결 후 배포(2장 원칙) |

## 6. 개발 메모

- 스키마를 바꿀 때: [table.md](architecture/table.md) 7장 체크리스트. 마이그레이션 테스트는 `test/migration_test.dart`(옛 버전 SQL로 DB를 만들어 업그레이드)에 케이스를 추가합니다.
- 코드 생성: `dart run build_runner build --delete-conflicting-outputs` (`sqlite3: 3.2.0` override 상태에서 동작 확인)
- 서버 상한(`pass_kuai_server/src/analyze/analyze-result.validator.ts` `ANALYZE_RESULT_LIMITS`)과 앱 DB 상한(`lib/database/tables/*`)은 **서버 ≤ 앱**을 유지합니다. 한쪽을 바꾸면 다른 쪽도 확인하세요.
- 원문 1000자 제한은 서버 DTO, 앱 입력창(`_maxInputLength`), 앱 DB 세 곳에 있습니다.

| 항목 | 처음 결정 | 이유 |
